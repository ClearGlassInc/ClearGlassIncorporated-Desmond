SEO blueprint

Fast static publishing with machine-readable authority.

GitHub Pages and Jekyll can support the full hub through Markdown posts, front matter, reusable includes, static JSON indexes, and lightweight client-side filtering.

  1. Metadata

    Use unique titles, descriptions, canonical URLs, Open Graph, Twitter cards, and `jekyll-seo-tag` for every post.

  2. Schema

    Emit `Blog`, `BlogPosting`, `BreadcrumbList`, `Organization`, `FAQPage`, and `ItemList` JSON-LD where relevant.

  3. Internal links

    Every article links to a pillar, a series page, two related posts, and one conversion path.

  4. Topic clusters

    Organize posts around governed AI, agents, cyber, OSINT, automation, financial crime, and high-trust systems.

  5. Share surfaces

    Add quotable pull quotes, social preview copy, copy-link actions, and section anchors for citation.

  6. Performance

    Static HTML/CSS, no heavy frameworks, font preconnects, compressed images, and progressive enhancement only.

Editorial engine

The system prompt that writes like the desk thinks.

Every Insights post is generated against a version-controlled editorial contract: E-E-A-T voice rules, a viral headline system, mandatory content architecture, SEO and JSON-LD requirements, Artemis platform integration, a strict output protocol, and refusal rules. The full prompt is versioned in the repo.

Mandatory content architecture

  • Defensible thesis in the first two sentences; quotable TL;DR block.
  • At least one system diagram and one implementation block (code, config, schema, or checklist).
  • A governance lens: what must be gated, logged, approved, or refused.
  • Two citation-ready pull quotes; internal links to one pillar, one series, two related posts, exactly one conversion path.

Output protocol & refusal rules

  • Strict order: front matter → TL;DR → body → pull quotes → JSON-LD → social pack → internal-link map.
  • Refuse thin topics: if a request can't support deep technical value or clear governance implications, propose a stronger adjacent topic instead.
  • Never fabricate benchmarks, incidents, customer stories, or statistics.
  • Defensive framing only, consistent with the SENTINEL charter.
