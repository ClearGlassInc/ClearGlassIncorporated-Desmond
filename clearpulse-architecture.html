§1Design Pillars

Every architectural decision in ClearPulse is validated against these pillars. They are non-negotiable and they compose the platform's defensibility.

P1
Traceability-first
UUID7 trace_id minted at ingestion, propagated through every stage. Every dashboard cell replays back to the originating byte.
P2
Explainable scoring
Every Risk Envelope carries weighted factors, contributing facts, and rule version. No black-box scores reach an analyst surface.
P3
Unified signal plane
Billing, behavior, and at-rest PHI exposure converge into one stream, one schema, one investigation graph.
P4
Forensic-grade lineage
Hash-chained, append-only, Merkle-anchored. The audit trail itself is the product.
P5
Deterministic-first, ML-augmented
Rules carry compliance weight. ML widens recall on novel patterns without surrendering defensibility.
P6
Identity-aware
Every event resolves to a stable EID — patient, provider, device, payer. Not transient source identifiers.
P7
Relationship-aware
The graph is a first-class store. Fraud rings and insider collusion live in edges, not rows.
P8
Tenant-isolated
Per-tenant streams, ledgers, KMS CMKs. Hard separation, by construction.

Why one envelope
CONTRACT
  • Single contract across rules, ML, graph, UI, and audit chain.
  • No phantom data: if it appears on screen, it has a trace_id and a hash.
  • Versioned: every envelope carries the rule_version and envelope_version it was scored under.
  • Forensic replay: reconstruct any historical decision from envelope + ledger byte + rule_version.
  • Identity-keyed: downstream baselines, graph features, incident grouping all key on EIDs.
  • Audit-self-contained: prev_hash + self_hash + merkle_root_ref let an independent verifier check integrity offline.
The Risk Envelope is the molecule of ClearPulse. Every macro behavior of the platform — explainability, defensibility, ML governance, multi-tenant safety — reduces to invariants we enforce on this object. — ClearPulse Architecture Office

§12Concrete System Design · Polyglot Data Plane

Three stores, one trace_id. Each store owns the shape of problem it is best at: Postgres is the system of record and the audit ledger, Redis is the hot transport and sketch layer, Neo4j is the relationship and feature plane. Nothing is duplicated without a hash that proves it came from the ledger.

Postgres · system of record
SOR + LEDGER
  • Append-only envelope_ledger, monthly range partitions
  • Hash-chain columns colocated with payload
  • Merkle anchors + RFC 3161 tokens
  • Per-tenant row level security
Redis · hot transport
STREAMS + SKETCH
  • Streams w/ consumer groups, at-least-once
  • HyperLogLog for cardinality per EID
  • Bloom for seen-before access tuples
  • Sorted sets for sliding-window scoring
Neo4j · relationship plane
GRAPH + FEATURES
  • Identity, billing, access, device topology
  • GDS projections for PageRank / Louvain
  • Materialized feature rows pushed to store
  • Read replicas for investigator traversal

§14Entity Resolution Internals · Fellegi-Sunter

§4 states the policy; here is the math and the blocking strategy that make it run at 5k eps. Each candidate field contributes a log-likelihood weight; the sum is thresholded into match / review / non-match. Blocking keeps the comparison space sub-quadratic.

Match weight accumulation
PYTHON
import math

# per-field m = P(agree | match), u = P(agree | non-match)
FIELDS = {
  "surname": (0.95, 0.004),
  "dob":     (0.98, 0.0007),
  "postal":  (0.90, 0.02),
  "phone":   (0.85, 0.001),
  "device":  (0.70, 0.05),
}

def match_weight(a, b):
    w = 0.0
    for f, (m, u) in FIELDS.items():
        agree = compare(a[f], b[f])      # Jaro-Winkler / exact
        if agree >= 0.9:
            w += math.log2(m / u)        # agreement weight
        else:
            w += math.log2((1-m) / (1-u))  # disagreement
    return w                            # total log-likelihood ratio

# thresholds calibrated on labeled pairs
def decide(w):
    if w >= 14.0:  return "MATCH"          # p ≳ 0.92
    if w >= 6.0:   return "REVIEW"         # active-learning queue
    return "NO_MATCH"
Blocking · sub-quadratic candidates
PYTHON
# never compare all-pairs; block on cheap keys first
def blocking_keys(rec):
    return {
      "k1": soundex(rec["surname"]) + rec["dob"][:4],
      "k2": rec["postal"][:3] + rec["surname"][:2],
      "k3": rec.get("phone_hash", "")[-6:],
    }

# candidates = union of records sharing ANY block key
def candidates(rec, index):
    out = set()
    for key in blocking_keys(rec).values():
        out |= index.get(key, set())
    return out

# merge writes a SAME_AS edge w/ confidence → Neo4j
def merge(a, b, w):
    p = 1 / (1 + 2**(-w))    # logistic of LLR
    graph.run(
      "MATCH (x:Patient{eid:$a}),(y:Patient{eid:$b}) "
      "MERGE (x)-[r:SAME_AS]-(y) SET r.p=$p",
      a=a, b=b, p=round(p, 4))

The decisive move from §5: train on the trace graph, not raw events. Features are materialized from the graph plane, versioned, and served point-in-time correct so a model never trains on data it could not have seen at scoring time. # registry-driven promotion; gate blocks the composite score
def promote(candidate, champion, holdout):
    m_c = evaluate(candidate, holdout)
    m_p = evaluate(champion,  holdout)

    gate = (
        m_c.recall   >= m_p.recall + 0.02   # +recall
        and m_c.fpr  <= m_p.fpr   + 0.10   # ≤+10% FP (§5)
        and m_c.auprc >= 0.80

§16Independent Audit-Chain Verifier

The legal moat is only real if a third party can verify it without trusting ClearPulse at runtime. This reference verifier recomputes the hash chain, rebuilds the Merkle root, and checks it against the public RFC 3161 timestamp and the WORM mirror — offline.

verify_chain.py · trustless replay
PYTHON · REFERENCE
import hashlib, json
from rfc3161ng import verify_timestamp

def sha256(b: bytes) -> bytes:
    return hashlib.sha256(b).digest()

def canonical(env: dict) -> bytes:
    # RFC 8785 JSON Canonicalization Scheme
    return json.dumps(env, sort_keys=True,
                      separators=(",", ":")).encode()

def merkle_root(leaves: list[bytes]) -> bytes:
    if not leaves: return sha256(b"")
    level = leaves
    while len(level) > 1:
        if len(level) % 2: level.append(level[-1])
        level = [sha256(level[i] + level[i+1])
                 for i in range(0, len(level), 2)]
    return level[0]

def verify_window(records, anchor):
    # 1) recompute the hash chain link by link
    prev = records[0]["prev_hash"]
    leaves = []
    for r in records:
        h = sha256(canonical(r["payload"]) + prev)
        assert h == r["self_hash"], f"BROKEN @ {r['trace_id']}"
        leaves.append(h); prev = h
    # 2) rebuild root, match the anchored value
    root = merkle_root(leaves)
    assert root == anchor["merkle_root"], "ROOT MISMATCH"
    # 3) prove the root existed at/before the claimed time
    assert verify_timestamp(anchor["tsa_token"], root), "BAD TSA"
    # 4) confirm the WORM mirror is byte-identical
    assert worm_fetch(anchor["worm_uri"]) == root, "WORM DRIFT"
    return "VERIFIED"     # tamper-evident, no runtime trust

Any failed assertion localizes tampering to a single trace_id and proves the rest of the chain remained intact — the property that turns an audit log into admissible evidence (FRE 902(13)–(14)).
