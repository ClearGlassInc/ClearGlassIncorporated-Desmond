# D. Technical SEO fixes

## Critical

1. Confirm a single preferred origin: `https://www.clearglassinc.com/`.
2. Ensure all alternate hostnames/protocols redirect once to the preferred canonical origin.
3. Validate `robots.txt`; do not block production assets required for rendering.
4. Generate/validate an XML sitemap containing only canonical, indexable, 200-status public URLs.
5. Add self-referencing canonical tags to all indexable pages.
6. Remove accidental `noindex`, staging canonicals, duplicate title tags, and conflicting canonical chains.
7. Ensure every public route returns the correct status code and no soft-404 template is indexed.
8. Validate mobile viewport, tap targets, responsive navigation, and CLS-sensitive dynamic elements.
9. Establish organization-wide metadata rules: unique title, meta description, one primary H1, logical H2/H3 hierarchy.
10. Validate structured data through Google Rich Results Test and Schema.org validator before release.

## High

- Compress/resize media; prefer AVIF/WebP where browser support permits.
- Set intrinsic image dimensions to reduce CLS.
- Lazy-load below-fold media without delaying the LCP image.
- Preload only truly critical font/image assets.
- Remove render-blocking or unused CSS/JS where measurement confirms benefit.
- Add descriptive alt text for meaningful images; empty alt for decorative images.
- Add breadcrumbs to deep content sections.
- Fix broken internal links and eliminate redirect chains in internal navigation.
- Add `lastmod` accurately in sitemap generation.
- Add meaningful 404 page with navigation and search/contact paths.
- Create an explicit content freshness field or visible “Last reviewed” date on technical content.

## Structured data policy

Use only when semantically valid and supported by visible content:

- `Organization` — homepage/about.
- `WebSite` — homepage; optional search action only if a real site search exists.
- `Product` — only genuine products with accurate offer data.
- `Service` — genuine consulting/service pages.
- `Article` / `TechArticle` — editorial/technical content.
- `BreadcrumbList` — hierarchical pages.
- `FAQPage` — only when the questions and answers are visibly rendered and eligible under current search-engine policies.

Never fabricate `Review`, `AggregateRating`, awards, credentials, prices, availability, offices, or customer claims.
